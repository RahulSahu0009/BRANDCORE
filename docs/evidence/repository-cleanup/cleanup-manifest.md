## POC endpoint security review

**Files reviewed:** `src/app/api/poc.py`, `src/app/main.py`, `src/worker.py`

**Finding:** `/api/poc/d1`, `/api/poc/r2`, and `/api/poc/ai` are mounted unconditionally
in `src/app/main.py` via `app.include_router(poc_router, prefix="/api")`. There is no
environment guard. In a deployed Worker these routes would be publicly accessible and
would perform real D1 writes and R2 puts.

**Risk level:** Medium for a deployed environment. No risk in local dev only.

**Current status:** BRANDCORE has not been deployed. No deployment approval has been
granted. The routes are safe for now.

**Proposed fix (requires Mritunjay's approval before implementation):**
Add a `BRANDCORE_ENV` binding check so POC routes return 404 in production:

```python
# In poc.py route handlers, add at the top of each handler:
env = request.scope.get("env")
if getattr(env, "BRANDCORE_ENV", "development") != "development":
    from fastapi import HTTPException
    raise HTTPException(status_code=404)
```

Or, simpler: remove the `poc_router` include from `main.py` before any deployment,
keeping the source and tests intact. This is the preferred approach per the prompt
("remove production route mounting while preserving tests/evidence").

**Action required:** No change made. Awaiting Mritunjay's approval.
